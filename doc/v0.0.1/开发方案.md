# Zhuandown v0.0.1 开发方案

## 1. 需求与范围

依据：[开发需求.md](./开发需求.md)。

本次包含两项工作：

1. 将根目录 README 调整为 Zhuandown 项目介绍，提供本项目的获取与构建说明，并说明与 Typedown 的关系。
2. 升级 Mermaid，适配新版渲染接口，解决旧版不支持的新语法以及预览、导出中的渲染问题。

本次只生成开发方案，尚未修改业务代码、README 或依赖，也未执行构建。

不纳入本次实施范围：解决方案、目录、程序集和命名空间重命名，安装包身份及应用内品牌替换，Logo 重设计，React、.NET 或整个前端构建体系升级，其他图表库改造。

## 2. 现状与问题定位

| 位置 | 已确认的实现 | 对本次开发的影响 |
| --- | --- | --- |
| `README.md` | 标题、介绍、克隆地址和贡献链接指向 Typedown，下载徽章指向其商店页面 | 需要调整项目归属，不能将上游下载入口作为 Zhuandown 下载入口 |
| `Dev/Typedown.Editor/package.json`、`yarn.lock` | Mermaid 声明为 `^8.13.10`，锁定版本为 `8.14.0`；React 17、react-scripts 5、TypeScript 4.5 | 升级依赖前需要验证现有工具链兼容性 |
| `src/components/Muya/lib/renderers/index.js` | 动态导入 `mermaid/dist/mermaid.core.js`，缓存默认导出 | 旧版内部文件路径需要替换为新版支持的包入口 |
| `src/components/Muya/lib/parser/render/index.js` | `renderMermaid()` 调用 `parse()`、`init()`，调用方不等待其完成 | 新版异步接口需要显式等待，并处理连续编辑时的过期结果 |
| `src/components/Muya/lib/parser/render/renderBlock/renderLeafBlock.js` | Mermaid 块先显示 `Loading...`，源码加入 `mermaidCache` | 保留现有代码块识别和调度入口，调整异步消费方式 |
| `src/services/exportHtml.js` | 导出前构造图表 DOM，调用 `init()` 后直接读取导出容器；临时切换为浅色主题 | 升级后必须等待 SVG 完成，避免导出空图及主题相互干扰 |
| `src/services/theme.ts` | 更新 `window.actualTheme` 和样式，没有直接触发 Mermaid 重绘 | 需要接入现有编辑器更新入口，验证已显示图表的主题刷新 |
| `config-overrides.js`、`Dev/Typedown/Controls/MarkdownEditor.cs` | 限制为单个 chunk；正式资源通过本地 `file://` 加载 | 必须验证新增图表模块在桌面离线环境可用 |

表中 `src/` 和 `config-overrides.js` 均相对 `Dev/Typedown.Editor/`。

当前实现确实存在版本和接口迁移问题，但尚无用户提供的具体失败代码。不能认定所有显示问题均由版本导致；实施时需要用官方样例和可复现文档分别确认语法、异步时序、样式或运行时问题。

## 3. Mermaid 版本与兼容性策略

2026-11-02 查询官方发布记录，最新稳定版本为 **12.2.0**，本方案以该版本为升级目标。实施开始时再次核对官方发布与 npm 稳定标签，固定经过验证的确切版本，同步生成 `yarn.lock`，不使用 `latest` 作为依赖值。

官方文档说明 Mermaid 12 的发布包面向 ES2024，Node.js 要求为 22.12.0 及以上。安装和构建应使用满足要求的 Node.js，并记录实际 Node、Yarn 版本；不能仅凭 WebView2 SDK 版本判断实际浏览器运行时是否兼容。

先在现有 CRA/webpack 配置中完成最小验证：包入口可解析、生产构建成功、基础图和新图类型可渲染、本地资源可离线加载。保留现有单 chunk 设置；只有实际验证表明其阻碍新版工作时，才针对该问题调整配置，并验证所有资源均正确输出到 `Resources/Statics`。

如出现兼容性阻塞，先核查 Node、Yarn、锁文件、包源及 WebView2 Runtime，再定位具体依赖或语法支持问题。不能为了构建方便自动降级为旧 Mermaid 并宣称满足“支持最新版本”；若必须扩大到构建体系迁移，先记录证据、影响与备选方案，再确认范围。

参考来源：[官方发布记录](https://github.com/mermaid-js/mermaid/releases)、[12.2.0 发布页](https://github.com/mermaid-js/mermaid/releases/tag/mermaid%4012.2.0)、[官方运行环境与 API 用法](https://mermaid.js.org/config/usage)。

## 4. 详细设计

### 4.1 README 调整

将标题、简介和 Logo 的替代文本改为 Zhuandown，使用中文说明 Windows Markdown 编辑器定位。克隆地址采用仓库当前 remote 对应的 `https://github.com/Hzrr97/Zhuandown.git`，贡献入口同步到本仓库。

删除原 Typedown 商店下载徽章，不编造 Zhuandown 发布页。现有截图和 Logo 如继续使用，应说明其来自上游，避免暗示已完成应用内品牌替换。

保留实际构建路径和工程名，例如 `Dev/Typedown.Editor`、`Dev/Typedown/Resources/Statics`、`Typedown.sln`，并解释这些是沿用的内部工程名称。保留 Debug、Debug_Local、Release 的现有运行说明，按工程文件核对平台支持，不直接沿用未经验证的架构承诺。补充经本次验证的前端工具版本和 Mermaid 版本说明。

增加来源说明，链接 `https://github.com/byxiaozhi/Typedown`，注明基于 Typedown 开发。保留仓库现有 LICENSE 和版权声明。

### 4.2 依赖与加载入口

在 `package.json` 固定目标 Mermaid 版本，通过 Yarn 正常生成锁文件，仅接受本次升级必需的依赖变化，不批量升级其他包。

`loadRenderer('mermaid')` 改为从新版公开入口加载，例如 `import('mermaid')`，继续返回默认导出并复用现有缓存。不引用旧版 `mermaid.core.js` 内部路径，不改造其他渲染器。

### 4.3 编辑预览

采用 `await mermaid.render(uniqueId, code)` 获取 SVG，再写入对应预览容器。显式设置 `startOnLoad: false` 和 `securityLevel: 'strict'`，预览主题继续使用 `window.actualTheme` 映射到 `dark` 或 `default`。

直接传入原始 Mermaid 源码，避免将源码先作为 HTML 清洗、再从 DOM 解析导致特殊字符或标签内容改变。不进行重复的预解析；若其他逻辑确需使用 `parse()`，必须等待其 Promise 并捕获异常。

异步处理遵循以下规则：

1. 在首次等待前提取并移走本批待渲染任务；异步期间新增的任务保留在队列中，不能在完成时整体清空。
2. 每次渲染使用唯一 SVG ID；提交前检查块版本、主题及目标 DOM 是否仍有效，旧结果不得覆盖新内容或已删除节点。
3. 单块失败只显示该块错误状态，清理失败产生的临时节点；后续有效输入应移除错误状态并恢复图表。
4. 对加载失败和渲染失败统一捕获，防止未处理的 Promise 拒绝或永久停留在 `Loading...`。

主题变化通过现有编辑器事件或实例更新路径触发 Mermaid 块重绘。先沿调用链复用现有机制，仅在必要处补充通知，不改造整体主题系统。

### 4.4 HTML、PDF 与打印导出

保留现有 `ExportHtml` 及桌面导出链路。逐块等待 Mermaid 渲染完成，得到完整 SVG 后再读取导出容器内容和回调桌面端，维持导出浅色主题的现有行为。

预览和导出复用同一 Mermaid 实例，会共享全局配置。采用一个仅服务于 Mermaid 的轻量串行入口，将“初始化配置、等待渲染、获取结果”放在同一任务内，避免浅色导出和深色预览交叉修改配置；不依赖导出后恢复旧配置解决并发问题，不设计通用任务框架。

从代码节点提取源码时避免重复 HTML 转义解码，验证 `<`、`>`、`&`、中文和引号保持原意。单个错误代码块输出明确占位，其他图表及正文仍可导出；临时容器通过 `finally` 清理。

保持严格安全级别，不为兼容语法而启用 `loose`。核对现有 DOMPurify 配置与新版 SVG、`foreignObject` 等结构的兼容性，防止合法图形被清洗破坏，同时不将原始源码或异常文本直接拼接为 HTML。最终 HTML 应内嵌 SVG，在离线打开及 PDF、打印链路中无需重新执行 Mermaid。

## 6. 实施顺序

1. 记录当前环境，选择官方新旧语法样例复现现状；有用户失败代码时优先加入样例。
2. 完成目标版本安装、公开入口加载和生产构建验证，尽早暴露环境或打包阻塞。
3. 实现共享渲染入口，接入预览、异步队列和错误恢复。
4. 接入导出并验证浅色导出与深色预览并发，补齐主题重绘。
5. 完成桌面离线、HTML、PDF 和打印回归，再将验证过的版本与构建步骤写入 README。
6. 检查最终差异，确认所有修改均属于本需求，记录验证结果与尚存限制。

## 7. 验证与验收

| 场景 | 重点与通过标准 |
| --- | --- |
| 常用旧语法 | flowchart、sequenceDiagram、classDiagram、stateDiagram-v2、erDiagram、gantt、pie 正常显示，连线与文本完整 |
| 新图类型 | 从目标版本官方文档选取 mindmap、timeline、xychart、block 和 architecture 等有效样例，预览与导出均有完整 SVG |
| 特殊内容 | 中文、引号、HTML 标签及转义字符按官方语法正确显示，保存后源码保持一致 |
| 连续编辑 | 快速输入、删除、撤销、切换文档及多块更新后，最终图形对应当前源码，无旧结果覆盖和长期 Loading |
| 错误恢复 | 无效语法仅影响当前块，其他图表继续显示；修正后恢复，不残留错误节点或未捕获异常 |
| 主题与并发 | 已显示图形随浅深色主题变化；深色编辑器导出浅色图后，继续编辑仍使用正确主题 |
| 导出 | 多图文档及包含错误图块的文档可完成 HTML 导出；离线 HTML、PDF 和打印不缺图、不截断 |
| 桌面加载 | Debug 开发服务与 Debug_Local 本地静态资源模式均可用；Release 资源完整，断网可渲染新旧图类型 |
| 无关功能回归 | 普通 Markdown、公式及原有其他图表的基本编辑和导出正常 |
| README | 展示 Zhuandown 名称及正确仓库地址，保留上游来源，命令与真实工程路径一致 |

自动化只覆盖有实际价值的异步行为：导出等待完成、单块失败隔离、过期结果不回写，以及主题配置串行处理。真实图形布局与 WebView2 离线加载采用桌面验证，不能仅凭模拟 Mermaid 的单元测试宣称兼容。

构建验证在 `Dev/Typedown.Editor` 下执行 `yarn install --frozen-lockfile` 和 `yarn build`，然后使用与项目匹配的 Visual Studio、.NET Core 3.1、Windows SDK 和 NuGet 配置构建实际验证的平台及配置。前端构建需实际成功，桌面构建需有真实成功结果后才能声明对应验证通过。

如环境、依赖或网络阻塞，分别记录已完成检查、失败命令、具体原因和未验证场景；不修改业务代码绕过环境问题。本方案中的兼容性与验收项目均为实施目标，尚未验证通过。
